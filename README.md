# CLARITEST

A tool generated utilizing prompting and RAG-augmented LLMs to improve the readability of generated test suites while preserving test semantics. This tool was generated by Shahd Metwally and Elias Samantzis (2026) for a Master's thesis at the University of Gothenburg and Chalmers University of Technology. It builds upon the work of previous Research Assistantship conducted by Nicole Quinstedt (2024) and Shahd Metwally (2025).

## Features of ClariTest
- **LLM Test Refactoring**: Refactoring unit tests using LLMs with RAG for context on original tests.
- **RAG**: Used to provide context to the LLM to help maintain semantic similarity with the original test cases.
- **Prompting Strategies**: Explores different prompting strategies for test readability improvement and semantic preservation.
- **Comprehensive Metrics**: Evaluates semantic preservations and code naturalness of the generated test cases.  

## How to run ClariTest
We run ClariTest using Chalmers Minerva GPU cluster:
1. First login in to Minverva:
```bash
ssh username@minvera.chalmers.se
```
2. Clone the repository:
```bash
git clone https://github.com/shahdmetwally/llm-test-readability.git
```
3. Install dependencies:
```bash
pip install -r requirements.txt
```
4. Get API keys for the models you want to use
```bash
export OPENAI_API_KEY="your-openai-api-key"
export HF_TOKEN="your-hugging-face-api-key"
export ANTHROPIC_API_KEY="your-anthropic-api-key"
```
5. Go to args_handler.py and edit the path to module and tests based on what you want to experiment on.

6. Run ClariTest using the .slurm files (we have files for Claude, GPT-Mini, Deepseek-Coder, Deepseek-V3):
```bash
sbatch run_experiment_claude.slurm
```

## Data
For our thesis experimentation we utilized Pynguin generated test suites for Python libraries and frameworks. This data was obtained from a previous Master's thesis: Adaptive Parameter Control for Search-Based Unit Test Generation by Erik Blomberg and Henrik Johansson. This data can be found in the /data directory.

## Results
The output directory includes the results of the experiments in the following format:
```
output_directory/
└── {model_name}/
    └── {module_name}/
        └── {prompt_strategy}/
            └── {run_number}/
                ├── {original_test_file_name}.py
                ├── {refactored_test_file_name}.py
                ├── {data_evaluation_metrics}.json
                └── {data_evaluation_metrics}.csv
```

### Data Evaluation Metrics
All data evaluation metrics are stored in the output directory as described above. These metrics include:
- **Semantic Preservation**: Measured by calculating the coverage, number of test cases, number of passing test cases, and number of failing test cases before and after refactoring. Then the difference is calculated and this is what we use to evaluate the semantic preservation of the refactored test cases. The bigger the difference, the less the semantic similarity with the original test cases.
- **Code Naturalness**: Measures the naturalness of the generated test cases using DAN which measures the structural readability by calculating the average predictability (cross-entropy) of statement sequences extracted from a Program Dependency Graph of the test cases. Then the difference is calculated and this is what we use to evaluate the code naturalness of the refactored test cases. Code naturalness in this study is used as a proxy for readability. The bigger the difference, the more natural the generated test cases are.
